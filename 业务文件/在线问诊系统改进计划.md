# 在线问诊实时会话系统改进计划

版本: v1.1
日期: 2026-05-20
适用范围: 业务、后端、前端、AI Agent、运维
维护原则: 后续所有改进以本文档为标准, 变更必须更新本文档

---

## 1. 目标与定位

目标是把 LiveKit 从会议能力升级为“业务会话层”, 形成问诊闭环:

业务系统创建问诊单 -> 后端签发 LiveKit Token -> Doctor / Patient / AI Bot 进入同一 Room -> 音视频+数据消息+AI 辅助 -> 形成可审计、可回放的问诊记录。

- 前端端口: 80

## 3. 核心对象与角色

### 3.1 对象

- Doctor: 医生用户(来自 RuoYi 用户体系)
- Patient: 病人用户(可轻量患者表或复用用户表)
- Consultation: 问诊单/会话记录
- LiveKit Room: 实时音视频房间
- AI Participant: 服务端 AI Participant

### 3.2 身份映射(标准)

- consultation_id = 1001
- room_name = consultation_1001
- doctor_identity = doctor_001
- patient_identity = patient_888
- ai_identity = ai_assistant_1001

## 4. 业务流程(标准)

### 4.1 创建问诊

医生选择患者 -> 创建 consultation -> 生成 room_name -> 保存 doctor_id / patient_id / status -> 返回问诊详情

### 4.2 医生进入

前端请求 /consultation/{id}/livekit-token -> 后端校验医生身份 -> 生成 token -> 返回 serverUrl + token

### 4.3 病人进入

病人验证 -> 请求 token -> 校验患者身份 -> 生成 token -> 进入同一 room

### 4.4 AI 进入

问诊开始 -> 后端调度 AI Agent -> AI 订阅音频 -> STT -> LLM -> 数据消息回传

## 5. 状态机(标准)

- WAITING: 等待进入
- IN_PROGRESS: 问诊中
- AI_SUMMARIZING: AI 生成摘要中
- FINISHED: 已结束
- CANCELLED: 已取消

## 6. 里程碑计划(主线)

### Milestone 0: 运行与配置稳定化

交付:
- 一键启动脚本
- 环境变量与默认配置对齐
- 基础健康检查

验收:
- 5 分钟内可恢复服务
- 日志可定位问题

### Milestone 1: 最小问诊闭环(MVP)

交付:
- 问诊单 CRUD
- LiveKit Token API(医生/病人)
- 问诊列表/详情/房间页

验收:
- 医生/病人进入同一房间
- 无权用户不可获取 token
- WAITING -> IN_PROGRESS -> FINISHED 正常流转

### Milestone 2: 身份与会话管理增强

交付:
- 参与者角色标识
- 加入/离开记录
- 数据消息(聊天/系统事件)
- 基础审计

验收:
- UI 显示角色
- 可追溯会话记录

### Milestone 3: AI 旁听(Mock)

交付:
- AI Participant 进房
- Mock transcript 数据消息
- 前端字幕面板
- transcript 入库

验收:
- AI 消息可展示
- transcript 可回溯

### Milestone 4: AI 真实能力

交付:
- 实时 STT
- LLM 医生辅助提示
- 病历摘要草稿

验收:
- 医生端可见 AI 提示
- AI 输出必须确认后入库

### Milestone 5: 生产增强

交付:
- 录制与存储
- 审计与脱敏
- 重连与异常恢复
- 监控与告警

验收:
- 多用户并发稳定
- 关键审计可追踪
